## Representative setup walkthrough

The following is a fictional, non-software request used to check the route. Its
answers are scenario inputs, not claims about a real organization or live system.
No external workspace was created or published during this walkthrough.

**Request:** “Set up a shared place for volunteers and an AI assistant to prepare
a monthly community session. Each session needs an agenda and preparation notes.”

Starting at the builder README selects [greenfield setup](../procedures/greenfield.md)
and then the shared discovery guide. The request establishes purpose, actors, and
the recurring unit (one session). It does not establish authoritative schedules,
access, or final destinations. Two focused questions materially change setup:

- “Where are the current date, venue, and topic maintained, and who can resolve
  disagreements?” Scenario answer: an existing shared calendar and the coordinator.
- “Where should agendas and preparation notes live, and can the assistant access
  it?” Scenario answer: the team's document space; volunteers can edit it, but the
  assistant's connector access has not been checked.

The builder can draft the landing page and reusable preparation instructions
while connector access is unresolved. It cannot claim it has installed those
routes or verified dates. The working view now contains:

| Dimension | Scenario decision |
|---|---|
| Purpose and actors | Help volunteers and an AI assistant prepare one monthly session. |
| Work unit | One session's agenda and preparation notes; recurrence justifies a procedure. |
| Sources | Calendar for current logistics; coordinator for unresolved logistics; supplied topic notes for content. |
| Capabilities | Volunteers can edit the document space; assistant drafts text now, live access remains unverified. |
| Constraints | Preserve existing access and instructions; do not infer confirmed dates from older notes. |
| Destinations | Draft in the current task until access is available; final landing page and session documents in the existing document space. |
| Completion | A volunteer can find current logistics, start preparation, locate the session documents, and check the agenda against the supplied topic and time available. |

The proposed landing page routes “check logistics” to the calendar, “prepare a
session” to the procedure, and “continue this session” to its existing documents.
It describes how volunteers use their editor and where the assistant returns
drafts. The procedure takes a session reference and source links, resolves missing
logistics, drafts the agenda, and checks coverage and timing. A specific month's
date, decisions, and agenda stay in that session's work record. No workflow is
needed until actual handoffs make a connected route useful.

Result: the guidance produces a usable draft and a precise access dependency.
Installation and live access verification remain unfinished in this fictional
scenario; the builder must report that limit instead of claiming a working
integration. An AI requester can supply the same facts and source pointers as a
brief, without a separate intake schema or broader authority.
